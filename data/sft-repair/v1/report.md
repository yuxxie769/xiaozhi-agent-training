# SFT 数据修订结果

**新版训练集已生成，共 606 条；步骤 6 已通过。尚未启动训练。**

## 这次为什么修

当前 SFT 诊断暴露了多轮控制、停止和事实依据问题。本轮先完善天气 C06、家居 HC06，再修订三个已有问题样本并补充示范。不能据此断定这三个旧样本是当前模型表现的主因，也不能把数据验收当作模型效果提升。

按最新要求，**取消全量重评，只评三个问题样本的原文与修正版，以及新增样本**。其他 553 条现有训练样本沿用旧评分，问题 4、5 原文保持不变。曾启动的全量天气重评已中止，分片日志记录了 247 条在内存中完成，但未形成完整评分文件，也未用于新版数据；家居全量重评未启动。[中止记录](recheck/interruption.json)。

## 做了哪些修改

评分器继续使用原有检查项，补充房间范围、降雨断言、日期和字段对应的依据要求；失败需提供主张和依据两侧证据。固定 16 个正反例各测 3 次，最终 48/48 符合预期，早期失败记录保留。[评分器验收](scorer-validation/v4/report.md)。

| 旧样本 | 修订内容 | 本轮评分 |
|---|---|---|
| T14-G004-P2 | “书房内还有”改为“可选的灯还有” | 原文失败，修正版通过 |
| S11-G03-P2 | 不再由多云保证不用带伞，改成明确限制和有条件建议 | 原文失败，修正版通过 |
| S15-G03-P2 | 分开当前参数和明确日期预报，去掉含糊的相对日期归属 | 原文仍通过，修正版通过；属于预防歧义的修订 |

只修改上述三处助手正文，设备目录、用户请求、调用和返回均未改。其他原文与历史评分保留。[逐条改文](targeted/edits.json)。

## 新增示范与数量

文字客户端 `deepseek-flash` 对 80 个不同变量组各尝试一次：家居 60、天气 20。使用统一提示词和完整 9 个非 MCP 工具，家居控制走对应模拟配置，天气在线查询。没有重复抽取失败任务。

| 新任务去向 | 数量 |
|---|---:|
| 合格并入库 | 50（家居 37、天气 13） |
| 未通过 | 23 |
| 待复核 | 5 |
| 生成失败，无完整轨迹 | 2 |
| 合计 | 80 |

78 条保存对话均完成评分：54 条自动通过、24 条自动失败。逐条证据复核后，4 条自动通过样本因无依据或不可靠表述转待复核；另 1 条自动失败样本含运行器提示，也转待复核。其他 23 条保持失败原文，未自动修正。

自动评分仍存在漏判，因此没有只凭自动通过就入库。隔离理由和原文引用见[证据复核](supplements/evidence-reviews.json)。两次生成失败均为用户轮次与种子不一致，错误记录保留，不计作模型答错。[生成错误](derived/generation-errors.json)。

最终对账：**553 条原样保留 + 3 条修正版 + 50 条新增 = 606 条训练样本**。完全重复为 0。原 28 条未通过、15 条待复核原样留档；新版合计未通过 51、待复核 20。盘点覆盖 677 条实际轨迹，另 2 次无完整轨迹的生成失败单独记录。[数量对账](derived/reconciliation.json)。
