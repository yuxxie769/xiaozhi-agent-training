# 独立训练项目迁移说明

本次把前一轮新增的训练准备文件从 xiaozhi-esp32-server 迁到并列目录 xiaozhi-agent-training。生成器、线上服务、原始评测目录以及用户原有改动不属于搬走范围。

## 搬走和复制的区别

| 内容 | 处理 |
|---|---|
| 上轮新增的导出脚本和测试 | 迁入本项目，原版本存 archive，活动版本调整本地路径 |
| 上轮新增的 training-data/v1 草稿 | 原样存 archive；提示词、配置、任务清单分放活动目录 |
| 上轮两次 tmp/training-data 试导出 | 早期结果存 archive；后一次结果存 data/candidates/v0 |
| 原始天气和家居轨迹 | 复制独立副本，原 server 文件保留 |
| 原评分和修订评分 | 复制所需快照，原文件保留 |
| 评分逻辑、模板和天气工具源码 | 复制必要内容，保留许可证与来源，不搬整个 server |

迁移先复制并检查 SHA-256，再对比离线导出结果，最后只清理上轮新增、已有可靠副本的训练文件。逐文件来源见根目录 migration-manifest.json。

## 为独立运行做的必要调整

导出器读取本项目 configs/data-v1.json，并从本地 vendor/legacy_evaluation 加载历史验证模块。配置中的轨迹、评分、提示词和工具源码全部使用相对于配置文件的路径。

家居种子模块保留原本不依赖 server 的校验函数和常量，删除 server 路径注入、模拟器导入及无关生成功能。该子集只用于读取历史种子并验证评分结构，不提供新的在线生成器。原始完整文件保留在 archive/upstream。

测试改为引用 scripts 和 configs。迁移后的回归检查在不包含 server 的环境中运行，比较关键 JSONL 是否与迁移前完全一致；这属于迁移验证，不推进新的训练数据版本。

## 历史路径和旧模型信息

历史 manifest、评分 revision 中的 Mac 绝对路径是原始来源记录，保持原样。活动脚本和配置不依赖这些路径。archive 中旧 README 的“型号未定”和旧命令不作为操作依据；已确认型号为 Qwen3.5-9B，以总文档为准。

之前本机 /private/tmp 中的 tokenizer 依赖虚拟环境不属于训练产物，不随项目迁移。没有下载的模型权重，也没有可迁移的训练 checkpoint。

## 复制到训练服务器

复制整个项目目录即可保留数据、规则快照、审计记录和脚本。先运行标准库单元测试，不需要安装或启动 agent server。目标服务器的训练环境、模型仓库版本、工具模板及 GPU 参数后续单独确认。

本次没有初始化 Git 仓库、推送远端、传输到远程训练服务器、生成新对话或启动训练。
